# ER-модель данных ситуационного центра — кейс 4

## 1. Перечень сущностей

| Сущность | Назначение в системе |
| :--- | :--- |
| **Site** | Справочник производственных участков птицефабрики (`site_01…site_05`: Птичники №1–3, Инкубатор, Кормоцех) и технологических зон (`zone_A`, `zone_B`, `zone_C`) из файла `01_данные/sites.csv`. Исключает дублирование названий и зон в таблицах телеметрии и инцидентов. |
| **Sensor** | Физический датчик микроклимата с уникальным суррогатным ключом `sensor_id`, установленный на конкретном участке (`site_id`). |
| **Measurement** | Единичное телеметрическое измерение показателя (`temperature`, `humidity`, `ventilation`), полученное от конкретного датчика (`sensor_id`). |
| **Incident** | Зарегистрированный инцидент (аварийное отклонение микроклимата или поломка оборудования), проходящий жизненный цикл устранения. |
| **Alert** | Оповещение, сгенерированное модулем Rules Engine при срабатывании правил `A-1…A-5` по результату анализа измерения. |
| **AuditEvent** | Неизменяемая (`append-only`) запись журнала информационной безопасности для фиксации всех переходов статусов и действий персонала. |

## 2. Атрибуты сущностей

### 2.1. Site (Производственный участок — справочник sites.csv)

| Поле | Тип | PK/FK | Обяз. | Описание |
| :--- | :--- | :---: | :---: | :--- |
| **site_id** | string | **PK** | да | Уникальный идентификатор участка (`site_01`…`site_05`) |
| **name** | string | — | да | Наименование объекта («Птичник №1», «Инкубатор», «Кормоцех») |
| **zone** | string | — | да | Технологическая зона безопасности (`zone_A`, `zone_B`, `zone_C`) для изоляции прав RBAC |

### 2.2. Sensor (Датчик телеметрии)

| Поле | Тип | PK/FK | Обяз. | Описание |
| :--- | :--- | :---: | :---: | :--- |
| **sensor_id** | string | **PK** | да | Уникальный первичный ключ датчика (`sns_001`) |
| **site_id** | string | **FK → Site.site_id** | да | Ссылка на производственный участок, где установлен датчик |
| **indicator** | enum | — | да | Измеряемый показатель: `temperature` / `humidity` / `ventilation` |
| **norm_min** | float | — | да | Нижняя граница технологической нормы для данного датчика |
| **norm_max** | float | — | да | Верхняя граница технологической нормы для данного датчика |
| **status** | enum | — | да | Техническое состояние датчика: `ACTIVE` / `OFFLINE` |

### 2.3. Measurement (Измерение / Показание датчика)

| Поле | Тип | PK/FK | Обяз. | Описание |
| :--- | :--- | :---: | :---: | :--- |
| **measurement_id** | string | **PK** | да | Уникальный первичный ключ измерения (`msr_0001`) |
| **sensor_id** | string | **FK → Sensor.sensor_id** | да | Единственный внешний ключ — ссылка на датчик-источник |
| **time** | datetime | — | да | Временная метка снятия показания (формат ISO 8601) |
| **value** | float | — | нет | Числовое значение показателя (`nullable` при обрыве связи `STALE`) |
| **status** | enum | — | да | Расчётный статус: `NORMAL` / `WARNING` / `CRITICAL` / `STALE` |
| **signature** | string | — | да | Криптографическая подпись пакета `HMAC-SHA256` |

### 2.4. Incident (Инцидент)

| Поле | Тип | PK/FK | Обяз. | Описание |
| :--- | :--- | :---: | :---: | :--- |
| **incident_id** | string | **PK** | да | Уникальный первичный ключ инцидента (`inc_001`) |
| **type** | enum | — | да | Категория сбоя: `temperature` / `ventilation` / `humidity` / `equipment` / `other` |
| **location** | string | **FK → Site.site_id** | да | Внешний ключ на производственный участок из справочника `Site` |
| **time** | datetime | — | да | Дата и время регистрации инцидента (ISO 8601) |
| **responsible** | string | — | нет | Табельный ID ответственного инженера (`nullable` в статусе `NEW`) |
| **status** | enum | — | да | Текущий статус ЖЦ: `NEW` / `ASSIGNED` / `IN_PROGRESS` / `CLOSED` |
| **deadline** | datetime | — | да | Нормативный срок закрытия задачи согласно SLA |
| **source** | enum | — | да | Канал создания: `mobile` / `sensor` / `auto` |

### 2.5. Alert (Оповещение)

| Поле | Тип | PK/FK | Обяз. | Описание |
| :--- | :--- | :---: | :---: | :--- |
| **alert_id** | string | **PK** | да | Уникальный первичный ключ оповещения (`alrt_0001`) |
| **measurement_id** | string | **FK → Measurement.measurement_id** | да | Ссылка на измерение, инициировавшее алерт |
| **severity** | enum | — | да | Уровень критичности: `WARNING` / `CRITICAL` / `STALE` |
| **action** | enum | — | да | Выполненное действие: `ALERT_CREATED` / `ESCALATED` / `DUPLICATE` |
| **at** | datetime | — | да | Временная метка генерации оповещения (ISO 8601) |

### 2.6. AuditEvent (Событие аудита ИБ)

| Поле | Тип | PK/FK | Обяз. | Описание |
| :--- | :--- | :---: | :---: | :--- |
| **event_id** | string | **PK** | да | Уникальный первичный ключ записи аудита (`evt_0001`) |
| **entity_type** | enum | — | да | Тип логируемой сущности: `incident` / `alert` |
| **entity_id** | string | **FK → Incident / Alert** | да | Идентификатор целевого инцидента (`incident_id`) или алерта (`alert_id`) |
| **action** | enum | — | да | Выполненная операция: `created` / `assigned` / `status_changed` / `closed` |
| **from_status** | string | — | нет | Исходный статус объекта до перехода |
| **to_status** | string | — | да | Новый статус объекта после перехода |
| **actor** | string | — | да | Идентификатор сотрудника или системного модуля (`e_101`, `system_rules_engine`) |
| **at** | datetime | — | да | Точная временная метка выполнения операции (ISO 8601) |
| **ip** | string | — | да | IP-адрес узла или терминала инициатора (`10.0.0.1`) |

## 3. Связи между сущностями

| Связь | Тип | Обоснование |
| :--- | :---: | :--- |
| **Site → Sensor** | `1:N` | На одном производственном участке (`site_id`) установлено несколько датчиков разных показателей (`sensor_id`). |
| **Site → Incident** | `1:N` | На одном производственном участке может быть зарегистрировано множество инцидентов во времени. |
| **Sensor → Measurement** | `1:N` | Один физический датчик (`sensor_id`) формирует непрерывный поток измерений (`measurement_id`). |
| **Measurement → Alert** | `1:N` | Одно аномальное измерение может породить первичное оповещение и последующие события эскалации. |
| **Incident → AuditEvent** | `1:N` | Каждый переход жизненного цикла одного инцидента фиксируется отдельной строкой в журнале аудита. |
| **Alert → AuditEvent** | `1:N` | Создание и эскалация каждого оповещения фиксируются в неизменяемом журнале безопасности. |
